# AGENTS.md

This file provides guidance for contributors and AI agents working in this repository.

## Project

A desktop offline practice tool for Dota 2 Invoker (Carl). It is not a 3D game; it is a training simulator focused on mechanics, combos, timing, and muscle memory.

Core features:

- Three-element orb queue
- Invoke and dual spell slots
- All 10 invoked spells
- Global optimal combo planning
- Preload combo mode
- Standard and legacy keybindings
- Quickcast and normal mouse cast modes
- Item bar with custom hotkeys
- Bilingual UI: Chinese default, English switchable
- Persistent configuration storage

## Language Rules

- Code comments must be written in Chinese.
- Comments must convey substantive information: factual descriptions or design rationale.
- Do not use conversational filler comments.
- Do not use emoji in code or comments.
- Technical terms should remain in English.
- UI strings are bilingual: Chinese (default) and English.
- README and public-facing documentation are written in English.
- Internal development documentation may be written in Chinese and is not tracked in Git.

## Source and Asset Rules

- Dota 2 images, sounds, and item icons are copyrighted by Valve.
- Use them only within this non-commercial project.
- Declare sources in `ATTRIBUTION.md`.

## Fix Quality Standard

- When fixing defects, balance security, scalability, performance, and architecture.
- Do not choose a patch just because it is fastest.
- Prefer structural fixes over temporary patches.
- Avoid speculative abstraction.
- Do not introduce frameworks without an actual requirement.
- If a fix would duplicate existing logic, extract shared logic into a common location.
- If a change forks an existing primitive, prefer one authoritative implementation used by all callers.

## New File Guidelines

- Prefer extending existing modules over creating new files.
- A new file should represent one cohesive responsibility.
- Name files by responsibility, not by feature or component.
- For non-obvious new modules, document the design decision in the file.

## Repository Boundaries

- `docs/` is kept locally for development notes.
- `docs/` is intentionally not tracked in Git.
- Build outputs such as `dist/`, `release/`, and `src-tauri/target/` are ignored.
- `src-tauri/gen/` is generated by Tauri and should not be committed.
